# 照片加载 V3：边界、测量与验收计划

本轮代码拆成三个可独立回滚的堆叠改动：列表/会话解耦，批量私有照片元数据，以及发布后缩略图生成与小缩略图组合读取。所有本地结果都来自合成数据；本文件不表示预览或生产已经部署、也不表示真机网络已经验收。

## 已实现的请求边界

- 日常首批 20 条，使用 `created_at + id` 游标；评论按当前已显示日常逐条分页，历史地点独立加载。分页不再作为照片删除或缓存清理证据。
- 同一页面的并发会话恢复共用在途任务。临时服务故障保留已确认视图；退出、换账号及跨标签页退出使旧响应失效。
- 最多 20 个 R2 表示共用一次 `/api/photo-meta`。Worker 每批执行一次 Auth、一次成员检查、一次媒体登记批量查询，并按出现的业务类型各执行一次关联批量查询。缩略图仅有限并发读取 R2 元数据。
- 批量结果只在当前账号、当前页面、当前请求序号中使用。IndexedDB 命中不读取正文；正文请求继续独立执行实时用户、成员、登记和业务关联检查。
- 日常与照片关联成功后，浏览器显式调用 `/api/photo-thumbnail`。生成失败不回滚日常或原图，界面提供重试；首次查看时的按需生成仍是恢复路径。
- 缩略图使用版本化私有路径和 HMAC 写入。相同进程内并发生成共用在途任务，Worker 写入前再次检查确定性衍生对象；已有同版本对象不会重新编码或覆写。
- 尚未取得元数据、但确认需要读取的现有小缩略图，可由一次 `compact=1` 正文请求返回正文与必要响应头。客户端仍检查 WebP MIME、512KiB 上限、版本、源版本、长度和 SHA-256；原图继续使用 1MiB 分段协议。
- 缩略图无法生成时，列表明确标记“已回退原图”，只在用户点击后重试，不因重新渲染静默重复下载大原图。

## 本地请求数量断言

| 场景 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 10 张可见照片、版本均已缓存 | 10 次单图元数据，0 正文 | 1 次批量元数据，0 正文 |
| 上述批次的 Worker Auth / 成员 / 登记查询 | 各 10 次 | 各 1 次 |
| 无元数据的小缩略图冷读取恢复 | 1 次元数据 + 1 次正文 | 1 次正文（携带元数据头） |
| 组合读取的正文传输 | 缩略图字节数 | 同一缩略图字节数 |

批量业务关联查询按批内业务类型最多各一次。R2 缩略图 `head` 仍按请求的缩略图表示执行，有限并发为 4；它不读取原图正文。标准批量核验成功的冷缓存路径仍是“一批共享元数据 + 每张缺失缩略图各一条正文”，不会为每张再发单独 `meta=1`。

## 预览及生产测量矩阵

每个候选部署使用相同 Git 提交、Worker 版本、Supabase 项目、账号、照片集合和操作顺序。先在预览测试，不通过时不进入生产。每个场景分别记录冷启动与连续调用，至少重复 30 轮后计算 P50/P95；异常轮不删除，单独标注状态码、重试次数和请求编号。

设备至少包括桌面 Chromium、一台 iPhone Safari 和一台安卓浏览器。手机使用实际无 VPN 网络，并分别覆盖 Wi-Fi、弱网/移动网络和一次人为断流恢复。

固定操作顺序：冷缓存进入、完整显示后普通刷新、切走再切回、等待一次 30 秒同步、加载更多、查看原图、退出并切换账号。每轮记录：

- 登录恢复、列表返回、首张缓存照片和首张冷缩略图显示时间；
- 批量元数据请求数/照片数、单图元数据请求数、正文请求数/字节数、缓存命中/未命中/写入失败；
- Vercel 与 Worker 各阶段耗时、冷启动标记、HTTP 状态、重试和 `X-Photo-Request-Id`；
- 页面跳动、长时间空白、前后台恢复和退出取消结果。

浏览器可在当前页面读取 `getPhotoLoadMetrics()` 的匿名计数；服务日志不得增加账号、照片 key、令牌、Cookie、正文或完整私人 URL。

## 待测决策

### Functions 地域

创建代码和环境完全相同的 `iad1`、`hnd1` 预览部署，使用上述矩阵对比端到端 P50/P95、错误率与冷启动。不得仅根据 Supabase 位于东京选择地域；最终以用户侧首图时间和服务阶段数据为准。生产地域本 PR 不变。

### Worker 内容缓存

先分离 Worker 的 Auth/profile/registry/business 与 `r2_read` 耗时。只有版本化缩略图的 R2 读取在冷路径 P95 中占比显著且重复读取可观时，才另行设计内容缓存。授权决定永不缓存；每次对外响应前仍实时校验用户、成员和业务关联；私人响应不得直接进入公共 CDN。

### 并发与原图读取

保持当前两个照片任务和原图串行分段。后续仅在预览对正文并发 2/3/4 做 A/B，测试手机、弱网、限流、断流和退出取消；元数据与正文分别统计。任何提高并发的方案必须同时改善首图或完整显示 P95，且不能增加 429/5xx、重复正文或内存峰值。原图并行分段或流式方案另开改动评审。

### 数据库与容量

分页稳定后，在真实认证/RLS 上下文中对第一页游标、当前记录评论和批量 `photo_key in (...)` 查询执行 `EXPLAIN (ANALYZE, BUFFERS)`。分别记录规划/执行时间、扫描行、缓冲命中及 `is_love_member()` 调用；管理员查询不能替代用户 RLS 结果。只有真实计划显示排序或过滤扫描成为瓶颈时才新增复合索引；不因记录增长预期直接升级付费实例。

## 发布、回滚和证据

发布顺序为 Worker 源码/生成单文件一致性检查、Vercel 预览、授权会话端到端验证、再申请生产授权。回滚按 PR 逆序撤销；批量元数据失败时客户端仍可回退单图路径，按需缩略图生成仍保留。任何预览/生产版本、真机结果、P50/P95 和 CI 状态都必须在实际运行后补记，未执行项标为“待验证”。
