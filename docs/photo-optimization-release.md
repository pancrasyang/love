# 照片鉴权合并与私有缩略图

本改动保留密码登录、Supabase Auth、RLS、HttpOnly Cookie、两任务并发、分段重试和 SHA-256 校验。数据库及已有原图均不修改。

## 行为

日常和历史地点列表请求 `variant=thumbnail`；点击“查看原图”才请求完整原图。两种表示分别缓存，关闭原图、退出或换账号时清理对应对象 URL。未配置新链路时，列表明确回退原图，不会把原图校验值发送给缩略图分段接口。

`PHOTO_WORKER_READS=1` 让 Vercel 只解封／续期 HttpOnly 会话凭据，照片授权全部交由 Worker。Worker 每次读取依次核对 Supabase 用户、两账号成员、RLS 可见的登记及业务关联。没有授权缓存，也没有向客户端签发可脱离会话使用的下载票据。缺少 `X-Love-Photo-Protocol: 2` 的旧 Worker 被拒绝，避免忽略新参数后读到未关联文件。

缩略图按 `derived/thumbnail-v1/<原图SHA-256>/<原图key>.webp` 保存到同一私有 R2 桶，不增加 `media_objects` 原图登记行。不存在时由 Vercel 读取并校验原图、用固定版本 sharp 编码，随后用独立 HMAC 密钥签名写入。签名约束原图 key、原图版本、完整缩略图哈希、长度及60秒时间窗；普通客户端不能写入／替换衍生图。生成限960×960、WebP quality78、最大512KiB；保留比例、不放大、按EXIF旋转，输出不带原始元数据。已有图的首次请求会产生服务器到服务器的原图读取；浏览器只接收缩略图。原图完整字节不被改写。

缩略图源版本过期会转入新的衍生路径；正常删除原图的已有流程同时清理当前版本缩略图。这里没有批量删除、迁移或旧 Storage 操作。

## 验证结果（本地，不能视为生产验收）

对前一轮独立核验的16张生产原图副本编码：33,875,173字节 → 965,616字节，减少97.15%；最大单张116,284字节。没有将这些本地图片或衍生图加入Git，也没有在此基准中上传R2。

运行 `node scripts/benchmark-photos.mjs` 和 `node scripts/benchmark-photos.mjs --delegated`。合成6MiB原图样本、不含生产凭据，每次上游操作模拟等待5ms：

| 场景 | 浏览器请求 | 旧链Supabase请求 | 新链Supabase请求 | 照片正文 |
| --- | ---: | ---: | ---: | ---: |
| 健康 | 7 | 46 | 28 | 6MiB |
| 第5段失败一次 | 8 | 53 | 32 | 6MiB |

单个原图分段由7次上游鉴权／查询降为4次。新链元数据也经过Worker（4次查询）。浏览器分段次数、并发及原图正文不变；列表正文降低来自缩略图，不能把鉴权合并说成减小原图本身。

回归覆盖旧链兼容、新链请求计数、匿名／撤销会话、未关联记录、版本412、旧Worker拒绝、缩略图编码、签名拒绝、防篡改、配置缺失回退、列表不下载原图、原图显式加载、缓存表示隔离、重新渲染不下载正文及退出清理。

## 发布顺序

1. 运行 `npm test`、`npm run check`、`node scripts/build.mjs`；Worker生成内容由 `node scripts/build-worker.mjs --check`核对。
2. 将本分支的 `worker/dashboard-worker.mjs` 发布到现有 `love-media-api`，保留 `LOVE_MEDIA` 私有桶绑定、Supabase配置、允许来源和日志设置。先记录真实部署版本并对照源码。原有上传／删除／读取接口保留兼容。
3. 在可信配置界面创建独立、随机、至少32字符的 `LOVE_PHOTO_PROXY_SECRET`，以Secret保存到Worker，以及Vercel服务器环境。不要复用会话加密密钥，不要在聊天／日志中传递。密钥未配置时缩略图安全回退原图。
4. Vercel先部署预览，保留 `PHOTO_WORKER_READS=0` 验证旧链；新Worker确认后在预览设置 `PHOTO_WORKER_READS=1` 并重新部署，真实核对16张缩略图、原图、哈希、缓存和登录权限。
5. 核对预览commit、Worker部署、真实结果后再发布生产并启用同名服务器环境开关。回滚时将该开关改为0并重新部署；无需修改R2公开状态或旧桶文件。

生产请求／传输量、真机无VPN、部署一致性必须另留真实证据。本地结果只证明实现和基准，不证明生产已启用。
